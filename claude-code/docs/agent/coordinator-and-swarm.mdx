## 当前结论

Argus 的新 subagent 行为统一走 Codex 风格协作工具：

- `spawn_agent`
- `list_agents`
- `wait_agent`
- `send_message`
- `close_agent`
- `resume_agent`

父线程负责判断是否真的需要并行工作。只有用户明确要求 subagents、delegation 或 parallel agent work 时，父线程才能调用 `spawn_agent`。

## 推荐流程

```text
用户明确授权并行
  -> 父线程识别可并行、非阻塞、互不重复的独立任务
  -> spawn_agent({ task_name, message, agent_type?, fork_turns? }) 创建 child thread
  -> list_agents / wait_agent 观察 Mailbox 和状态
  -> send_message 发送后续具体补充信息
  -> close_agent 关闭不再需要的分支
  -> 父线程汇总最终结果、证据和阻塞原因
```

父线程不应该把“我在等结果”“进度如何”这类轮询写进用户正文。等待结果应走 `wait_agent`，补充具体信息才使用 `send_message`。

## Thread Graph

每个 child agent 是独立 thread，并通过 graph edge 连接到 parent thread。UI 和历史恢复都基于 thread graph 与 subagent snapshot，而不是解析旧文本通知。

```text
main thread
  -> explorer child thread
  -> worker child thread
```

edge 只有 `open` 和 `closed` 两种持久状态；运行态由 watcher / registry / mailbox 事件提供。

## OpenMythos

OpenMythos 只提供拆分建议。它不会自动创建 worker，也不会绕过 feature gate。是否派发由父线程在 Codex 工具规则下决定。
