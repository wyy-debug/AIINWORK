## 当前结论

Argus 不再使用旧的 Coordinator ticket、WorkerRuntime、OpenMythos 自动派发或 `<task-notification>` 协议作为新会话执行链路。所有新 subagent 行为统一走 Codex 风格工具：

- `spawn_agent`
- `send_input`
- `wait_agent`
- `list_agents`
- `close_agent`
- `resume_agent`

## 模型职责

父线程负责判断是否需要并行工作。只有用户明确要求 subagents、delegation 或 parallel agent work 时，父线程才能调用 `spawn_agent`。

推荐流程：

```text
用户明确授权并行
  -> 父线程识别可并行的独立任务
  -> spawn_agent 创建 child thread
  -> list_agents / wait_agent 观察状态
  -> send_input 发送后续具体指令
  -> close_agent 关闭无用分支
```

## 线程图

每个 child agent 是独立 thread，并通过 graph edge 连接到 parent thread。UI 和历史恢复都基于 thread graph，而不是解析旧文本通知。

```text
main thread
  -> explorer child thread
  -> worker child thread
```

edge 只有 `open` 和 `closed` 两种持久状态。运行时状态由 watcher 提供。

## OpenMythos

OpenMythos 只提供拆分建议。它不会自动创建 worker，也不会绕过 feature gate。是否派发由父线程在 Codex 工具规则下决定。
