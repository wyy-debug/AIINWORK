## Current Model

Argus uses the Codex MultiAgentV2 collaborative tool surface:

- `spawn_agent`
- `send_message`
- `followup_task`
- `wait_agent`
- `close_agent`
- `list_agents`

The parent thread decides whether parallel work is actually useful. The model may call `spawn_agent` only when the user explicitly asks for subagents, delegation, or parallel agent work.

## Recommended Flow

```text
User explicitly authorizes parallel work
  -> identify independent non-blocking tasks
  -> spawn_agent({ task_name, message, agent_type?, fork_turns? })
  -> continue useful local work
  -> wait_agent for mailbox update drains when needed
  -> send_message({ target, message }) for queue-only information
  -> followup_task({ target, message }) for concrete follow-up work
  -> close_agent({ target }) for branches that are no longer needed
  -> summarize final results, evidence, and blockers for the user
```

Use the canonical path returned by `spawn_agent` or `list_agents` as `target`, for example `/root/read_runtime`. Bare relative names are accepted from the current agent path; nicknames and internal ids are not public target handles.

Do not expose internal task ids, thread ids, or agent self-talk to the user. Summarize outcomes in normal assistant prose.

## Thread Graph

Every child agent is an independent thread connected to the parent by `agentPath` and `parentAgentPath`. UI, recovery, list, close, and target resolution should prefer canonical paths and mailbox events over transcript text or legacy thread ids.

```text
/root
  -> /root/read_runtime
  -> /root/fix_tests
```

OpenMythos may suggest task decomposition, but it does not authorize or start agents automatically.
