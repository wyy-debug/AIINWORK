## 当前协议

Argus 只暴露 Codex 风格协作工具：

- `spawn_agent`
- `send_input`
- `wait_agent`
- `list_agents`
- `close_agent`
- `resume_agent`

旧的 `AgentDispatchPlan -> dispatch_ticket -> WorkerRuntime/OpenMythos auto-dispatch` 链路已经移除。旧 transcript 只做只读降级渲染，不再参与新会话工具列表，也不再作为执行入口。

## Spawn 输入

`spawn_agent` 使用 Codex 参数：

```json
{
  "message": "Review the runtime permission changes and report risks.",
  "agent_type": "explorer",
  "fork_context": true,
  "model": "gpt-5.2",
  "reasoning_effort": "high"
}
```

也可以用 `items` 传结构化输入。`agent_type` 默认是 `default`，常用角色是 `explorer` 和 `worker`。

## Spawn 输出

`spawn_agent` 只返回：

```json
{
  "agent_id": "agent_123",
  "nickname": "Explorer"
}
```

后续结果通过 `wait_agent`、`send_input`、`close_agent`、`resume_agent` 获取或控制。

## 使用约束

只有用户明确要求 subagents、delegation、parallel agent work 时，模型才应该调用 `spawn_agent`。复杂、深入、彻底分析本身不等于授权派生子智能体。

默认禁止 nested subagents。高级配置打开后，也必须受 depth limit 和 session concurrency limit 约束。

## Thread Graph

每个 subagent 都是独立 thread。运行时持久化 parent-child edge：

```text
parent_thread_id -> child_thread_id
edge_status: open | closed
```

运行时支持：

- children / descendants 查询
- close subtree
- resume closed agent
- status watcher
- max concurrent threads per session
- duplicate objective guard

状态对齐 Codex：

- `PendingInit`
- `Running`
- `Completed(message)`
- `Errored(message)`
- `Interrupted`
- `Shutdown`
- `NotFound`

## OpenMythos 的边界

OpenMythos 现在只做建议层：可以给出任务拆分建议和诊断预览，但不生成 ticket、不写 worker plan、不自动 spawn。真正的执行只能通过 Codex 风格工具完成。
