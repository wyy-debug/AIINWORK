## Current Protocol

New sessions expose only the Codex MultiAgentV2 tool surface when subagents are enabled:

- `spawn_agent`
- `send_message`
- `followup_task`
- `wait_agent`
- `close_agent`
- `list_agents`

Legacy dispatch aliases, dispatch tickets, natural-language gates, and old transcript-only execution inputs are not part of the current model-visible protocol.

## Spawn Input

`spawn_agent` accepts Codex-style parameters:

```json
{
  "message": "Review the runtime permission changes and report risks.",
  "task_name": "review_runtime_permissions",
  "agent_type": "explorer",
  "fork_turns": "none",
  "model": "gpt-5.2",
  "reasoning_effort": "high"
}
```

`task_name` must be a relative lowercase name using only letters, digits, and underscores. The tool returns the canonical path form, for example `/root/review_runtime_permissions`.

`fork_context` and `items` are old protocol fields and are rejected. A full-history fork, `fork_turns: "all"`, cannot be combined with `agent_type`, `model`, or `reasoning_effort` overrides.

## Spawn Output

`spawn_agent` returns only the model-visible task path and optional nickname:

```json
{
  "task_name": "/root/review_runtime_permissions",
  "nickname": "explorer"
}
```

Internal task ids, agent ids, thread ids, output files, and launch-control details are not model-visible output.

## Control Tools

- `send_message({ "target": "/root/review_runtime_permissions", "message": "..." })` queues information for the target and does not start a new turn.
- `followup_task({ "target": "/root/review_runtime_permissions", "message": "..." })` assigns concrete follow-up work and starts or resumes the target when needed.
- `wait_agent({ "timeout_ms": 30000 })` drains mailbox updates and returns `{ message, timed_out, sequence, updates }`.
- `list_agents({})` returns `{ agents: [{ agent_name, agent_status, last_task_message }] }`, including `/root`.
- `close_agent({ "target": "/root/review_runtime_permissions" })` closes the target and descendants.

Targets are canonical paths such as `/root/review_runtime_permissions`, or bare relative names from the current agent path when unambiguous. Nicknames, internal task ids, and hidden agent ids are not public target handles.

Use `wait_agent` for results, `send_message` for queue-only information, and `followup_task` for work that should trigger an agent turn. A `wait_agent` drain consumes only model-relevant mailbox events: final notifications, inter-agent messages, and interaction events. Progress, tool start, tool completion, and token usage events remain registry telemetry and are not returned in the mailbox drain.

## Thread Graph And Mailbox

Each subagent is a child thread connected to its parent by canonical agent path. The registry stores `agentPath`, `parentAgentPath`, graph status, runtime status, last task message, and mailbox sequence events. `threadId` and `parentThreadId` remain historical/debug fields; listing, target resolution, and subtree close use canonical paths as the source of truth.

The visible status vocabulary follows Codex: `running`, `{ completed }`, `{ errored }`, `interrupted`, `shutdown`, and `not_found`.
