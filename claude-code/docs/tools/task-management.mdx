## 双轨架构

MTL-Code 的任务管理由两套实现组成：

| 维度 | TodoWrite V1 | Tasks V2 |
| --- | --- | --- |
| 启用场景 | SDK、pipe 或 Todo V2 未启用 | 交互式 REPL 或 `MTL_CODE_ENABLE_TASKS=1` |
| 存储 | 进程内 `AppState.todos[sessionId]` | `~/.claude/tasks/<taskListId>/<id>.json` |
| 数据模型 | `content / status / activeForm` | `id / subject / description / owner / status / blocks / blockedBy` |
| 持久化 | 进程退出后丢失 | 跨进程保留 |
| 并发安全 | 单会话单写者 | 文件锁、高水位 ID 和依赖检查 |

`TodoWriteTool.isEnabled` 与 `TaskCreateTool.isEnabled` 互斥，避免同一会话同时使用两套任务系统。

## TodoWrite V1

TodoWrite 是全量替换操作：每次调用传入完整 `todos[]`，覆盖之前的状态。全部任务完成时会清空列表，避免 UI 持续显示已完成噪声。

TodoWrite 还带一个验证提醒：主线程一次完成 3 个以上任务且没有验证步骤时，tool result 会提醒模型在最终总结前做本地验证，或询问用户是否需要单独 verifier subagent。这个提醒不能自动授权 subagent 派发；只有用户明确要求 delegation、parallel agent work 或 subagents 时，才能使用 Codex 风格协作工具。

## Tasks V2

Tasks V2 使用文件系统持久化，每个任务是独立 JSON 文件。核心字段：

```json
{
  "id": "1",
  "subject": "Fix auth bug",
  "description": "Detailed task description",
  "activeForm": "Fixing auth bug",
  "owner": "agent-name",
  "status": "pending",
  "blocks": [],
  "blockedBy": [],
  "metadata": {}
}
```

任务列表 ID 的来源优先级：

1. `MTL_CODE_TASK_LIST_ID`
2. teammate 上下文中的 team name
3. `MTL_CODE_TEAM_NAME`
4. leader 设置的 team name
5. 当前 session id

任务 ID 通过文件锁和高水位标记分配，删除任务后不会复用旧 ID。

## 依赖与认领

依赖通过双向字段维护：

- `blocks`：当前任务完成前，会阻塞哪些任务。
- `blockedBy`：当前任务被哪些任务阻塞。

删除任务时，系统会从其他任务的 `blocks` / `blockedBy` 中清理引用。

`claimTask()` 会检查任务是否存在、是否已被认领、是否已完成、是否被依赖阻塞，以及当前 agent 是否已经忙碌。失败原因会以结构化 reason 返回，便于 UI 和模型做下一步决策。

## Plan Mode 配合

Plan Mode 和任务系统互补：

1. Plan Mode 限制为只读工具，让模型先理解再行动。
2. 模型可用 Tasks 创建计划和依赖。
3. 用户批准后退出 Plan Mode。
4. 模型按依赖顺序执行，并用 TaskUpdate 标记进度。

任务管理工具本身是状态管理操作，不应触发写文件权限弹窗；真正修改项目文件仍由对应工具负责权限检查。
